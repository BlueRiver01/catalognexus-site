Field guide / Catalog operations

A changed supplier file
needs a review decision.

Before updating a catalog, check what the file represents, how records match, and which changes need a human decision. Keep the review report separate from the import file.

By CatalogNexus · Updated November 10, 2026 · AI-assisted editorial content · Fictional examples

Download the free review worksheet

Seven review decisions

  1. Scope
  2. Identity
  3. Duplicates
  4. Numbers
  5. Changes
  6. Import rules
  7. Decision record

1. Confirm what each snapshot contains.

Keep the untouched supplier exports. Record their dates, selected supplier or category, and export filters. A missing record may mean the export was filtered, rather than the product being discontinued.

Decide the unit of comparison: one product, one sellable variant, or one location’s inventory record. A product-level key cannot reliably distinguish several variants of the same product.

2. Treat identifiers as text.

Confirm with the supplier that the chosen key identifies the same item across both snapshots. Preserve 00123 as text; do not assume it means the same item as 123. Check any proposed trimming or case normalization against the supplier’s rules before using it.

Excel can convert identifiers and long numbers during import. Microsoft documents using text column types and, in supported versions, automatic-conversion settings to preserve the original values. Formatting after a conversion does not restore missing digits. Microsoft’s identifier-preservation guidance.

3. Resolve blank and repeated keys first.

A repeated key is a question about identity. It may reflect variants, image rows, location records, or an actual duplicate. Do not silently keep the first row or sum stock without a documented business rule.

Our proposed comparison workflow holds every record for an ambiguous key out of automatic matching on both sides. This is a conservative review rule, not a universal definition of a duplicate.

Count excluded source records separately from added, removed, changed and unchanged unique keys. Combining these different units can hide a mismatch.

4. Check units before comparing values.

  • Are prices per item, case, pack, or another unit?
  • Is currency explicit and the same on both sides?
  • Do blanks mean unknown, unchanged, unavailable, or zero?
  • Is stock for the same warehouse and timestamp scope?

A price moving from 40 USD to 42 EUR is not a verified 5% increase. Record the currency change and request context. Likewise, a stock change is a difference between supplied snapshots, not proof of current availability.

6. Read the destination’s actual import rules.

A comparison report is evidence for a reviewer. It is not automatically a valid import file. Confirm required headers, matching behavior, blank-value semantics, variant rules and preview behavior in the destination’s current documentation.

For example, Shopify documents that, when overwriting products with matching handles, a blank non-required column can clear the existing value. Its inventory CSV has a different workflow with current/new quantities and safety validation. Do not transfer one importer’s blank-value rule to another. See Shopify product imports and Shopify inventory CSVs.

Use an appropriate test environment or a controlled, approved test and retain a recovery plan before changing a live catalog. This guide and our generic checks do not certify platform compatibility.

7. Leave a short decision record.

Record the two source filenames, export dates, matching rule, excluded groups, change counts, reviewer, and decisions still awaiting confirmation. Link each accepted or rejected change to its key and reason. Preserve the original inputs and any approved import separately.
